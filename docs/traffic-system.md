# 交通系統 (Traffic System)

WebCity 的交通系統模擬車輛在車道級別的移動，包含通勤、貨運和服務車輛。

---

## 車輛 (Vehicle)

### 車輛屬性

| 屬性 | 說明 |
|------|------|
| `id` | 唯一識別碼 |
| `length` | 車體長度（世界座標） |
| `width` | 車體寬度（世界座標） |
| `lane` | 所在車道（0-based） |
| `edgePath` | 路徑邊列表 |
| `edgeIndex` | 當前邊索引 |
| `edgeProgress` | 當前邊上的行進距離 |
| `speedMultiplier` | 隨機速度因子 (0.8~1.0) |
| `stallTime` | 停滯累計時間（秒），超過 30 秒則強制消失 |
| `arrived` | 是否已到達目的地 |

### 車輛類型

根據車體長度分類：

| 長度 | 類型 | 權重 |
|------|------|------|
| ≥ 0.58 | bus (公車) | - |
| ≥ 0.35 | truck (卡車) | 10% |
| ≥ 0.24 | van (貨車) | 15% |
| < 0.24 | car (轎車) | 75% |

### 服務車輛

| 類型 | 長度 | 寬度 |
|------|------|------|
| police (警車) | 0.22 | 0.09 |
| fire (消防車) | 0.55 | 0.125 |
| health (救護車) | 0.30 | 0.10 |
| garbage (垃圾車) | 0.45 | 0.125 |

## 車道圖 (LaneGraph)

### 概念

LaneGraph 將格子級的道路網路轉換為車道級的連線圖，支援精確的車輛移動模擬。

### 組成

- **ConnectionPoint（連接點）**: 每個道路格子的每條車道在每個方向都有 entry（進入）和 exit（出發）點
- **LaneEdge（車道邊）**: 連接兩個 ConnectionPoint 的路段

### 邊類型

| 類型 | 說明 |
|------|------|
| `straight` | 直行路段 |
| `turn` | 轉彎路段（使用 Bezier 曲線） |
| `lane_change` | 換道路段 |
| `merge` | 合流路段 |

### 車道寬度

每條車道的橫向偏移: `LANE_WIDTH = 0.18` 格

### 路口判定

roadFlags 中有 3 個以上方向旗標的格子為路口（intersection）。路口內的格子是「透明的」，不產生自己的連接點。

---

## 車道邊的曲線幾何

### Bezier 曲線

車道邊的轉彎路段使用**二次 Bezier 曲線**（quadratic Bezier）表示：
- 起點: `edge.from.position`
- 控制點: `edge.bezierControl[0]`
- 終點: `edge.to.position`

直行路段使用線性插值。

控制點的計算使用進入和離開方向的切線交點，產生近似 90° 圓弧的曲線。

### 弧長查找表

三次 Bezier 曲線使用弧長查找表（arc-length LUT）進行等速插值，通過二分搜尋將距離映射到參數 t。

## 車輛移動

### 基礎速度

```
邊速度 = EDGE_SPEED × (道路速限 / REFERENCE_LIMIT) × speedMultiplier × 壅塞速度倍率
```

- `EDGE_SPEED` = 14 世界單位/秒
- `REFERENCE_LIMIT` = 50（速限 50 = 1.0 倍速）

### 前方碰撞偵測

車輛在前方 5 個世界單位 (`LOOKAHEAD_DISTANCE`) 內進行三層碰撞檢查：

#### 1. 同邊前車偵測 (findGapAhead)

在同一邊路徑（`edgePath`）上搜尋前方最近的車輛：
```
gap = 前車進度 - 我的進度 - 我的半長 - 前車半長
```
搜尋跨越多條邊，直到超過前視距離。

#### 2. 紅燈偵測 (findRedLightDistance)

檢查前方是否有紅燈。車輛在停止線偏移 0.25 格處停下。

#### 3. 跨邊 AABB 碰撞 (findCrossEdgeGap)

使用 **空間雜湊 (SpatialHash)** 偵測不同車道邊上但物理位置接近的車輛：

- **空間雜湊格大小**: 1.0 世界單位
- **檢查半徑**: 2.0 世界單位
- **AABB 縮放**: 1.1（10% 安全邊距）

跨邊碰撞只在**合流兄弟邊**（目的地相同的連接點）之間發生。優先級規則：
- `progressRatio` 更高（更接近合流點）→ 優先通過
- 相同 progressRatio → 較低 ID 優先

碰撞判定使用方向投影：
```
前向距離 = 相對位置投影到我的前進方向
橫向距離 = 相對位置投影到我的垂直方向
若 橫向距離 ≤ (我的半寬 + 對方半寬) × 1.1
  → gap = 前向距離 - (我的半長 + 對方半長) × 1.1
```

### 停滯消失

車輛停滯超過 30 秒 → 強制消失。初始有 0~5 秒的隨機抖動。

### 公車特殊行為

公車到站時會停靠 2 秒（`BUS_DWELL_SECONDS`），期間不移動。

## 壅塞 (Congestion)

### 壅塞率

```
壅塞率 = 車輛數 / 容量
```

### 速度倍率

| 壅塞率 | 速度倍率 |
|--------|---------|
| ≤ 0.5 | 1.0（正常） |
| ≤ 0.8 | 0.8（中度壅塞） |
| ≤ 1.0 | 0.5（嚴重壅塞） |
| > 1.0 | max(0.05, 1 - 壅塞率) |

## 紅綠燈 (Traffic Lights)

### 放置規則

只有在 **兩條主要道路** (FOUR_LANE 或 SIX_LANE) **同時在南北和東西兩個軸向交叉**的路口才會設置紅綠燈。

### 相位

| 相位 | 南北 | 東西 |
|------|------|------|
| 0 | 綠燈 | 紅燈 |
| 1 | 紅燈 | 綠燈 |

### 相位時間

- 3 方向路口: 2 秒
- 4 方向路口: 4 秒

相位開始時有基於位置的隨機偏移，避免所有紅綠燈同步。

## 貨運系統 (FreightSystem)

### 運作流程

每 tick：
1. 工業建築產生貨物（每棟 2 單位/tick）
2. 商業建築消耗貨物（每棟 1 單位/tick）
3. 產生的貨物進入倉儲
4. 消耗量從倉儲扣除
5. 不足的部分為缺貨量

### 外部貨物來源

- **鐵路貨運**: 每列貨運火車 +10 貨物/tick
- **機場貨運**: 消耗機場的貨物配額
- **鐵路外部連接**: 連接地圖邊緣的鐵路可帶入外部貨物

### 缺貨影響

缺貨比例 = 缺貨量 / 消耗量（0~1）。缺貨會影響商業區的成長。

## 通勤系統

### 通勤流程

每個通勤市民（工作年齡、有住所和工作場所）按以下流程決定交通方式：

```
1. chooseMode() 決定交通模式
   ├─ WALK (距離 ≤ 3) → 不產生車輛，加入行人池
   ├─ BUS/METRO/RAIL/FERRY → 不產生車輛
   │   ├─ 加入最近站點的 dailyRiders
   │   ├─ 產生 FIRST_MILE 行人行程（住所→站點）
   │   └─ 產生 LAST_MILE 行人行程（站點→目的地）
   └─ DRIVE → 產生通勤車輛
       ├─ 檢查快取路徑
       ├─ 無快取 → findRoadPath + refineLanePathVariants
       ├─ 隨機選擇車道變體（分散到不同車道）
       └─ 儲存到 CommuteCache
```

### 通勤時段

| 時段 | 方向 | 車輛產生 | 行人密度倍率 |
|------|------|---------|-------------|
| 早高峰 (6~9) | 住所→工作 | 最大 | 1.0 |
| 午間 (10~16) | 隨機商業交通 | 少量 | 0.3 |
| 晚高峰 (17~21) | 工作→住所 | 最大 | 1.0 |
| 夜間 (22~5) | 無 | 無 | 0.05 |

### 每 tick 產生數量

```
maxPerTick = max(5, ceil(合格通勤者數 / 4))
```

4 ticks 的高峰期內要把所有通勤者都發出去。

### 通勤快取 (CommuteCache)

儲存市民的通勤路徑（LaneEdge 序列），避免每次重新計算。

- **路線共享**: 相同起訖點的市民共享預計算的 LaneEdge 路徑變體
- **路線變體**: `refineLanePathVariants` 為每個起訖點計算多條車道變體
- **格子索引**: 每個路徑記錄通過的格子，道路變更時只失效受影響的路線
- **世代機制**: `roadGeneration` 遞增標記路網變更，舊世代的快取自動失效
- **失敗快取**: 無路徑的起訖點也記錄為 `failed`，避免重複搜尋
- **延遲重算**: 失效路線在下次使用時才重新計算（不一次全部重算）

### 道路切斷的即時處理

當道路被拆除時，立即檢查所有在職市民的工作場所是否仍可達：
- 不可達 → 立即失業（`workplaceId = null`）
- 不等到 jobRelocationTick（避免市民在空中的車輛消失）

## 行人系統 (Pedestrian System)

### 行人代理 (PedestrianAgent)

每個行人是獨立的代理，在人行道圖上移動。

| 屬性 | 說明 |
|------|------|
| `citizenId` | 對應的市民 ID |
| `tripType` | 行程類型 |
| `edgePath` | 人行道邊路徑 |
| `state` | 當前狀態 |
| `speedMultiplier` | 個人速度倍率 (0.5~1.0) |
| `lateralOffset` | 隨機橫向偏移（視覺效果） |
| `age` | 已存活秒數（超過 120 秒消失） |

### 行程類型

| 類型 | 說明 |
|------|------|
| `FULL_WALK` | 完整步行通勤 |
| `FIRST_MILE` | 第一哩（住所到大眾運輸站） |
| `LAST_MILE` | 最後一哩（大眾運輸站到目的地） |
| `DECORATIVE` | 裝飾性行人（隨機出現在人行道上） |

### 行人狀態

| 狀態 | 說明 |
|------|------|
| `WALKING` | 行走中 |
| `WAITING_SIGNAL` | 等紅綠燈 |
| `WAITING_CROSSING` | 等待過馬路 |
| `ARRIVED` | 已到達目的地 |

### 行人數量限制

```
上限 = clamp(人口 × 5%, 50, 2000)
```

裝飾性行人最多佔 15%。

### 行人速度

基礎速度: 1.5 世界單位/秒

|------|------|

| `crosswalk_wait` | 斑馬線等候點 |
| `building_entrance` | 建築入口 |

### 邊類型

| 類型 | 說明 |
|------|------|
| `sidewalk` | 人行道段 |
| `crosswalk` | 斑馬線（過馬路） |

### 人行道生成規則

- 人行道節點沿道路邊緣生成（無相鄰道路的那一側）
- 人行道寬度: 0.14 世界單位
- 斑馬線連接路口兩側的等候點

## 停車系統 (Parking System)

### 停車位容量

```
每棟建築停車位 = max(1, floor(工人數 / 2))
```

### 停車流程

1. 車輛到達目的地 → 嘗試停車
2. 停車位未滿 → 停車成功
3. 停車位已滿 → 嘗試附近建築的停車位（按距離排序）
4. 全部已滿 → 溢出計數 +1

## 服務車輛 (Service Vehicle Manager)

巡邏式服務車輛在服務覆蓋範圍內的道路上行駛。

### 車輛類型

- 警車 (police)
- 消防車 (fire)
- 救護車 (health)
- 垃圾車 (garbage)

### 配置

| 參數 | 值 |
|------|-----|
| 每設施巡邏車數 | 2 |
| 全類型最大總數 | 20 |
| 最少覆蓋道路格數 | 2 |

### 行為

- 服務車輛是交通模擬中的真實車輛
- 遵守紅綠燈、排隊等交通規則
- 在覆蓋範圍內的道路上隨機巡邏
- 到達路徑終點後重新規劃新路徑
