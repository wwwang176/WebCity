## 電力系統 (PowerGrid)

### 發電廠類型

支援 5 種發電方式：`wind`, `solar`, `coal`, `gas`, `nuclear`

### 電力需求

每棟建築的用電量 = base + perCapita × (居民數或工人數)

| 區域類型 | 基礎用電 | 每人用電 |
|---------|---------|---------|
| 住宅 | 0.25 | 0.025 |
| 商業 | 0.50 | 0.04 |
| 工業 | 1.00 | 0.06 |
| 辦公 | 0.50 | 0.025 |

基礎設施用電：

| 設施 | 用電量 |
|------|--------|
| 警局 | 5 |
| 消防局 | 5 |
| 醫院 | 9 |
| 小學 | 4 |
| 高中 | 6 |
| 大學 | 8 |
| 垃圾場 | 8 |
| 水廠 | 10 |
| 污水廠 | 8 |
| 公園 | 1.5 |
| 墓園 | 1.5 |

### 覆蓋機制

使用兩階段 BFS：

1. **完整覆蓋**: 從電廠出發，沿道路和建築無限 BFS 擴散 → 顯示網路可達範圍
2. **供電覆蓋**: 從電廠出發，每經過一個建築扣除其用電量 → 電廠輸出耗盡後停止

## 貨運系統 (FreightSystem)

> 貨運系統已獨立為 [freight-system.md](freight-system.md) — 涵蓋兩階段 BFS 供貨、FreightTradeCollector、進出口貿易、Supply Rate、FreightPage UI。

### 供電比

```
供電比 = 總發電量 / 總需求量
```
供電比 < 1 時，部分建築將無電可用。

### BFS 中繼與終點

電力/供水的 BFS 將格子分為三種：

1. **中繼格** — 接收並傳播電力/水，BFS 繼續擴散：
   - 有道路 (`roadType != NONE`)
   - 有建築 (`buildingId != 0`)
   - 是基礎設施位置

2. **終點格** — 只接收，不傳播（不加入 BFS queue）：
   - 有分區規劃但無建築的空格（`zoneType != NONE && buildingId == 0`）
   - 例如：道路旁的空工業區格可以接電，但不會把電傳到更遠的格子

3. **不可達格** — 完全跳過：
   - 無道路、無建築、無分區的空地

這表示空的分區格子只要鄰接有電的道路或建築就會有電，但一旦建築蓋起來（`buildingId > 0`），該格子就會升級為中繼格，可以將電力傳給更遠的鄰居。

## 服務調度 (Service Dispatch)

服務車輛（消防車、救護車、靈車）通過道路網路調度。巡邏車輛的渲染與交通規則詳見[交通系統 — 服務車輛](traffic-system.md#服務車輛-service-vehicle-manager)。

> **注意**：垃圾收集不使用服務車輛調度，而是使用加權隨機收集機制（詳見[垃圾處理](#垃圾處理-garbageservice)）。

### 服務車輛速度

| 車輛類型 | 基礎速度 (格/tick) |
|---------|-------------------|
| 消防車 | 3 |
| 救護車 | 3 |
| 靈車 | 2 |

### 行程估計

```
行程時間 = ceil((路徑長度 / 速度) × (1 + 壅塞率))
```

壅塞率基於路徑上的壅塞路段和全局車輛密度估算。

### 設施分區

設施可以被分配到特定行政區，僅回應該區域的事件。未分配的設施回應所有區域。

## 警察服務 (PoliceService)

### 警局負載系統

警局具有容量限制（預設 1000），超載時犯罪減少效果降低。

#### 每人警力需求

```
需求 = 0.3 × 加權乘數
```

**住宅居民**（依教育程度）：

| 教育程度 | 乘數 | 需求 |
|---------|------|------|
| NONE | 2.0 | 0.6 |
| ELEMENTARY | 1.1 | 0.33 |
| HIGH_SCHOOL | 0.6 | 0.18 |
| UNIVERSITY | 0.3 | 0.09 |

**工作場所工人**（依區域類型）：

| 區域 | 乘數 | 需求 |
|------|------|------|
| 工業 | 1.5 | 0.45 |
| 商業 | 1.0 | 0.3 |
| 辦公 | 0.5 | 0.15 |

每位市民同時產生住宅需求（依教育）和工作場所需求（依區域）。

#### 超載效果

犯罪減少效果 = 基礎效果 × min(1, 1/loadRatio)

- 負載率 ≤ 1.0：犯罪減少正常
- 負載率 2.0：犯罪減少效果減半
- 負載率 5.0：犯罪減少效果僅 20%

### 犯罪減少

- 每個覆蓋該格的警局: 犯罪率 -30（受負載率縮減）
- 上限: 犯罪率最多減少 -60

### 犯罪率計算（SimulationLoop）

```
基礎犯罪率 = min(50, 人口 × 0.02)
每格犯罪率 = 基礎犯罪率 + 警察犯罪減少值 × 負載效率
```

## 消防服務 (FireService)

### 消防局負載系統

消防局具有容量限制（預設 2000），超載時火災損害增加。

#### 每人消防需求

```
需求 = 0.3 × 加權乘數
```

**住宅居民**（依入住率）：

```
乘數 = 1 + occupancyRatio
```

| 入住率 | 乘數 | 需求 |
|--------|------|------|
| 0% | 1.0 | 0.3 |
| 50% | 1.5 | 0.45 |
| 100% | 2.0 | 0.6 |

**工作場所工人**（依區域類型）：

| 區域 | 乘數 | 需求 |
|------|------|------|
| 工業 | 2.0 | 0.6 |
| 商業 | 1.2 | 0.36 |
| 辦公 | 0.8 | 0.24 |

#### 超載效果

火災損害隨負載率從 10% 遞增至 80%：

| 負載率 | 損害 | 說明 |
|--------|------|------|
| ≤ 1.0 | 10% | 正常覆蓋 |
| 1.0~3.0 | 10%→80% 線性 | 逐漸惡化 |
| ≥ 3.0 | 80% | 等同無覆蓋 |

### 火災機制

#### 起火概率

```
基礎起火概率 = min(0.02, 0.001 + 人口 × 0.000005)
每 tick 以此概率嘗試起火
```

起火時隨機取樣 10 個格子，找到有區域建築的格子即起火。

#### 火災過程

1. 起火 → 建立 ActiveFire（持續 3 ticks）
2. 每 tick 倒數
3. 完成後結算損害：
   - **有消防覆蓋**: damage = 10%（受負載率影響）
   - **無消防覆蓋**: damage = 80%

#### 焦黑判定

```
若 damage ≥ 0.5 → 建築變為焦黑 (reserved = BURNED)
```

焦黑建築：
- 渲染為深灰色，無燈光
- 不產生收入
- 不計入容量
- 2% 機率/成長 tick 被建商自動清除

#### 火災風險

基於道路距離：
- 無消防局: 風險 = 1.0
- 覆蓋範圍外: 風險 = 0.8
- 覆蓋範圍內: 風險 = (道路距離 / 預算) × 0.5

## 醫療服務 (HealthService)

### 健康加成

- 每個覆蓋該格的醫院: +20 健康值
- 上限: +35

### 醫院負載系統

醫院具有容量限制（預設 1500），高污染地區的居民會增加醫院使用量。

#### 每位市民醫療需求

```
需求權重 = 0.3 + 0.3 × (住所污染值 / 255)
```

| 污染值 | 需求權重 | 說明 |
|--------|---------|------|
| 0 | 0.3 (30%) | 正常就醫率 |
| 128 | 0.45 (45%) | 中等污染 |
| 255 | 0.6 (60%) | 高污染，使用量翻倍 |

#### 城市負載率

```
負載率 = 全市覆蓋市民加權需求總和 / 全市醫院容量總和
```

#### 負載率對死亡率的影響

| 負載率 | 死亡率乘數 | 說明 |
|--------|-----------|------|
| ≤ 1.0 | 0.3 | 醫院正常運作 |
| 1.0 ~ 2.0 | 0.3 → 1.0 線性 | 逐漸惡化 |
| ≥ 2.0 | 1.0 | 等同無醫院覆蓋 |

#### 無覆蓋 + 高污染額外懲罰

無醫院覆蓋的市民，污染直接增加死亡率：

```
污染死亡乘數 = 1 + 0.5 × (住所污染值 / 255)
```

| 污染值 | 死亡率乘數 |
|--------|-----------|
| 0 | 1.0 |
| 128 | 1.25 |
| 255 | 1.5 |

完整死亡率計算詳見[市民系統 — 死亡系統](citizen-system.md#死亡系統)。

## 垃圾處理 (GarbageService)

### 全域覆蓋

垃圾場使用 Infinity BFS 覆蓋整個道路網路（與殯葬服務相同）。距離影響收集優先級但不限制覆蓋範圍。

### 垃圾產生

垃圾由 `GarbageSewageProduction` 模組按區域類型計算，使用**實際入住人口**（非建築容量）：

| 區域類型 | 基礎產量 | 每人產量 |
|---------|---------|---------|
| 住宅 | 0.05 | 0.005 |
| 商業 | 0.1 | 0.005 |
| 工業 | 0.2 | 0.01 |
| 辦公 | 0.02 | 0.002 |

```
每棟建築垃圾 = base + perCapita × 實際居民數或工人數
```

產量按建築累積，達到 ≥1 時產生一袋垃圾（PendingGarbage）放在建築門口。

### 收集流程（加權隨機）

每 service tick，每座垃圾場：
1. 計算收集預算 = min(COLLECTION_RATE, 容量剩餘空間)
2. 掃描所有等待中的垃圾袋，按距離加權（weight = 1/cost）
3. 加權隨機選取建築，收走該建築的垃圾
4. 重複直到預算用完或無袋可收
5. 收到的垃圾直接加到 facility.currentLoad

近距離建築更容易被選中，遠距離建築也有機會但機率較低。

### 焚燒

每 service tick：`burned = min(currentLoad, BURN_RATE)`

### 設計目標

production ≈ collection > burn，使容量有意義：

| 常數 | 值 | 說明 |
|------|-----|------|
| COLLECTION_RATE | 140 | 每設施每 service tick 最多收集量 |
| BURN_RATE | 90 | 每設施每 service tick 焚燒量 |
| DEFAULT_CAPACITY | 2000 | 每設施容量 |

1 座垃圾場可承受 ~3,500 人口（burn ≈ production），5,000 人口時 facility 開始填滿，7,000+ 需要第二座。

### 幸福度影響

建築門口的垃圾袋影響居民幸福度（per-citizen）：

| 條件 | 懲罰 |
|------|------|
| 每袋垃圾 | -3 |
| 等待 > 30 ticks 的袋子 | -8 |
| 上限 | -15 |

### 建築面板警告

| 袋數 | 等級 |
|------|------|
| < 3 | 不顯示 |
| 3-4 | 黃色 |
| ≥ 5 | 紅色 |

### 未收集垃圾污染

```
污染懲罰 = min(100, 未收集袋數 × 2)
```

### 設施污染

負載率 > 50% 的設施產生額外地面污染：
```
額外污染 = round(負載率 × 40)
基礎污染 = 20（每設施格）
污染半徑 = 5（曼哈頓距離）
```

### 腐爛

等待超過 600 ticks 的垃圾袋自動消失。

### 每週統計

使用 7 天環形緩衝區追蹤 Produced/wk 和 Burned/wk。

## 污水處理 (SewageService)

### 污水產生（基於用水量）

污水產量由 `GarbageSewageProduction` 模組計算，基於各區域的用水量乘以污水比率：

| 區域類型 | 污水比率 |
|---------|---------|
| 住宅 | 85% |
| 商業 | 90% |
| 工業 | 90% |
| 辦公 | 92% |

```
每棟建築污水 = 該建築用水量 × SEWAGE_RATE[區域類型]
```

### 處理能力

每座處理廠容量 2250 單位。處理廠必須**鄰接道路**且**有電力供應**才能運作。未處理污水 = max(0, 產生量 - 連接處理能力)。

### 水源污染

```
水源污染 = 未處理污水 × 5
```
每個排放口最多排放 80 污染。注意：污水產生的是**水源污染**（非地面污染）。

## 殯葬服務 (DeathCareService)

### 覆蓋模式：全城道路可達

殯葬服務使用**全城覆蓋**模式（繼承 `GlobalCoverageService`）：墓園服務範圍涵蓋整個道路網絡，沒有距離限制。任何透過道路連接到墓園的位置都可被服務。

每座墓園獨立計算道路可達性（per-cemetery BFS, Dijkstra 無預算限制），距離影響的是**收集優先度**（加權隨機，近的更可能被收集）。

### 收集模型：預算制（與 GarbageService 對齊）

每座墓園每 service tick 可收集 **3 具屍體**（`COLLECTION_RATE = 3`）。收集採用**加權隨機**演算法（`collectPending`，由 `GlobalCoverageService` 提供）：

- 權重 = `1 / max(1, roadCost)`：距離越近越可能被選中
- 每次選中一個位置 → 找最近且有容量+預算的墓園
- 立即收集（同 tick 內完成，無運送延遲）

### 死亡 → 處理流程

```
市民死亡 → reportDeath(x, y) → 加入 pendingDeathQueue { x, y, waitTicks }
  ↓
tick() Step 1: waitTicks++ → 超過 1800 tick 自動分解移除
  ↓
tick() Step 2: collectPending() — 加權隨機收集，每墓園預算 3 具/tick
  → 收集成功: currentLoad++ → 從佇列移除
  → 無覆蓋/容量滿: 留在佇列，下次 tick 重試
  ↓
tick() Step 3: processCemeteries() — 每墓園火化 min(currentLoad, CREMATION_RATE)
```

### 墓園容量與 fallback

收集時檢查 `capacity - currentLoad > 0`（容量 50）。最近墓園滿了 → 自動分配到次近的有容量墓園。所有墓園都滿 → 停止收集 → 屍體留在街上持續扣幸福度 → 玩家必須擴建。

### 火化處理

每 service tick 每座運作中的墓園：`min(currentLoad, CREMATION_RATE)` 具屍體被火化（CREMATION_RATE = 1）。

### 吞吐量平衡

| 項目 | 每 service tick | 每天（4 ticks） |
|------|----------------|----------------|
| 收集（最大） | 3 | 12 |
| 火化處理 | 1 | 4 |

收集速度（12/天）高於火化速度（4/天），屍體會在墓園內堆積。容量 50 在中型城市會產生擴建壓力。

### 屍體清除機制

| 觸發條件 | 說明 |
|---------|------|
| 收集車收走 | 正常流程：collectPending → currentLoad++ → 火化 |
| 自然分解 | waitTicks ≥ 1800（~12 遊戲週）→ 自動移除 |
| 玩家拆除建築 | demolish 工具拆除 → `clearPendingAt(x, y)` |
| 建商清除焦黑建築 | BURNED 建築自動清除時觸發 |
| 建商清除廢棄建築 | ABANDONED 建築重建時觸發 |

### 幸福度影響

**Per-citizen**：只有家門口有屍體的市民受影響。

| 等待時間 | 每具屍體懲罰 |
|---------|------------|
| < 30 ticks | -10 |
| ≥ 30 ticks | -25 |

### 建築面板警告

| 條件 | 等級 | 訊息 |
|------|------|------|
| 1~2 具屍體等待 | 黃色 | Dead body awaiting pickup (N) |
| ≥ 3 具屍體等待 | 紅色 | Dead body awaiting pickup (N) |

### 每墓園負載追蹤

每座墓園獨立追蹤：
- `currentLoad`: 目前儲存的屍體數（等待火化）
- `todayReceived` / `todayCremated`: 今日統計
- `deathDaily` / `recentDaily`: 7 天環形緩衝區

### Overview 顯示

Death Care 獨立群組，每座墓園一行 + 彙總行：

```
⚰ Cemetery    Bodies 3 / 50                        [Normal]
⚰ Death Care  Awaiting pickup 12 · Deaths 5/wk · Cremated 4/wk  [12 awaiting]
```

- 墓園行：`currentLoad / capacity`
- 彙總行：街上等待數 + 每週死亡/火化統計（永遠顯示，不隱藏）
- 無墓園時顯示「No cemetery」+ 等待數

## 公園服務 (ParkService)

### 覆蓋方式

使用歐幾里得距離（預設半徑 5 格）。只有連接道路的公園才有效。

### 效果

| 效果 | 每公園 | 上限 |
|------|--------|------|
| 地價加成 | +15 | +30 |
| 污染減少 | -20 | -40 |
| 幸福度加成 | +5 | +10 |

## 設施運作條件 (Facility Operational)

所有市政設施（電廠、水廠除外）必須同時具備**電力**和**供水**才能運作：

```
isFacilityOperational(x, y, infraType) =
  (hasPower || 電力豁免) && (hasWater || 供水豁免)
```

| 豁免類型 | 豁免設施 |
|---------|---------|
| 電力豁免 | 電廠（power） |
| 供水豁免 | 水廠（water）、污水廠（sewage） |

未運作的設施不提供覆蓋效果，也不處理任何需求。

當設施的運作狀態變更時（例如取得電力/供水，或失去電力/供水），系統會**立即重算所有服務覆蓋**，確保覆蓋地圖即時反映設施狀態。

## 過載警告 (Overload Warnings)

區域建築面板會根據服務負載率顯示分級警告：

| 服務 | 黃色（over capacity） | 紅色（overstretched） |
|------|---------------------|---------------------|
| 警察 | 負載率 > 1.0 | 負載率 > 2.0 |
| 消防 | 負載率 > 1.0 | 負載率 > 2.0 |
| 醫療 | 負載率 > 1.0 | 負載率 > 2.0 |
| 垃圾 | 負載率 > 0.5 | 負載率 > 1.0 |
| 殯葬 | 1~2 具屍體等待 | ≥ 3 具屍體等待 |

基礎設施面板顯示 Need/Capacity 欄位及過載指示。學校在註冊超過容量時顯示需求警告。殯葬在建築面板顯示「Dead body awaiting pickup」。

## 覆蓋方式比較

| 方式 | 使用服務 | 說明 |
|------|---------|------|
| BFS 路網擴散（預算耗盡制） | 電力、供水 | 沿道路/建築 BFS 中繼擴散，分區空格為終點（接收但不中繼），每經過建築扣除需求量直到預算耗盡 |
| 道路距離覆蓋 | 警察、消防、醫療、教育、垃圾 | 從設施出發沿道路 BFS，在道路距離預算內的格子視為覆蓋 |
| 全城道路可達 | 殯葬 | 從設施出發沿道路 Dijkstra 無限擴散，整個道路網絡皆可服務，距離影響回應速度 |
| 連接道路判定 | 污水 | 只判斷設施是否鄰接道路 |
| 歐幾里得半徑 | 公園 | 直線距離內覆蓋 |

## 道路距離覆蓋演算法 (Road Coverage Flood)

大多數市政服務使用 Dijkstra 道路距離覆蓋，而非簡單的歐幾里得半徑。

### 道路格通過成本

```
成本 = BASE_COST / (speedLimit × laneFactor)
```

- `BASE_COST` = 100
- `laneFactor` = 車道數 / 2（雙車道 = 1×）
- 更快更寬的道路 → 成本更低 → 覆蓋更遠

### 各服務的覆蓋預算

| 服務 | 預算 | 說明 |
|------|------|------|
| 警察 | 30 | 硬性覆蓋範圍 |
| 消防 | 30 | 硬性覆蓋範圍 |
| 醫療 | 40 | 硬性覆蓋範圍 |
| 垃圾 | 80 | 硬性覆蓋範圍 |
| 小學 | 20 | 硬性覆蓋範圍 |
| 高中 | 30 | 硬性覆蓋範圍 |
| 大學 | 45 | 硬性覆蓋範圍 |
| 殯葬 | ∞（無限制） | 全城道路可達；35 僅用於 overlay 漸層著色基準 |

從設施出發沿道路 Dijkstra 擴散，累積成本 ≤ 預算的格子視為覆蓋。殯葬服務例外：無預算限制，覆蓋整個連通道路網絡。

## 服務覆蓋分數

### 單格服務分數

每個格子的服務分數（0~10）：

| 服務 | 有覆蓋時的分數 |
|------|--------------|
| 電力 | +2 |
| 供水 | +2 |
| 警察 | +1 |
| 消防 | +1 |
| 垃圾 | +1 |
| 醫療 | +1 |
| 教育 | +1 |
| 殯葬 | +1 |

### 城市服務覆蓋率

`getResidentialServiceRatios()` 計算所有住宅建築的各服務覆蓋比率（0.0~1.0），用於城市層級的幸福度和吸引力計算。

### 城市服務覆蓋分數

```
分數 = 電力覆蓋率 × 2 + 供水覆蓋率 × 2
     + 警察覆蓋率 + 消防覆蓋率 + 垃圾覆蓋率
     + 醫療覆蓋率 + 教育覆蓋率 + 殯葬覆蓋率
     + (平均污染 < 10 ? 1 : 0)
```
