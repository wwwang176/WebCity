## 電力系統 (PowerGrid)

### 發電廠類型

支援 5 種發電方式：`wind`, `solar`, `coal`, `gas`, `nuclear`

### 電力需求

每棟建築的用電量 = base + perCapita × (居民數或工人數)

| 區域類型 | 基礎用電 | 每人用電 |
|---------|---------|---------|
| 住宅 | 0.25 | 0.025 |
| 商業 | 0.50 | 0.04 |
| 工業 | 1.00 | 0.06 |
| 辦公 | 0.50 | 0.025 |

基礎設施用電：

| 設施 | 用電量 |
|------|--------|
| 警局 | 5 |
| 消防局 | 5 |
| 醫院 | 9 |
| 小學 | 4 |
| 高中 | 6 |
| 大學 | 8 |
| 垃圾場 | 8 |
| 水廠 | 10 |
| 污水廠 | 8 |
| 公園 | 1.5 |
| 墓園 | 1.5 |

### 覆蓋機制

使用兩階段 BFS：

1. **完整覆蓋**: 從電廠出發，沿道路和建築無限 BFS 擴散 → 顯示網路可達範圍
2. **供電覆蓋**: 從電廠出發，每經過一個建築扣除其用電量 → 電廠輸出耗盡後停止

### 供電比

```
供電比 = 總發電量 / 總需求量
```
供電比 < 1 時，部分建築將無電可用。

### BFS 中繼與終點

電力/供水的 BFS 將格子分為三種：

1. **中繼格** — 接收並傳播電力/水，BFS 繼續擴散：
   - 有道路 (`roadType != NONE`)
   - 有建築 (`buildingId != 0`)
   - 是基礎設施位置

2. **終點格** — 只接收，不傳播（不加入 BFS queue）：
   - 有分區規劃但無建築的空格（`zoneType != NONE && buildingId == 0`）
   - 例如：道路旁的空工業區格可以接電，但不會把電傳到更遠的格子

3. **不可達格** — 完全跳過：
   - 無道路、無建築、無分區的空地

這表示空的分區格子只要鄰接有電的道路或建築就會有電，但一旦建築蓋起來（`buildingId > 0`），該格子就會升級為中繼格，可以將電力傳給更遠的鄰居。

## 服務調度 (Service Dispatch)

服務車輛（消防車、救護車、垃圾車、靈車）通過道路網路調度。巡邏車輛的渲染與交通規則詳見[交通系統 — 服務車輛](traffic-system.md#服務車輛-service-vehicle-manager)。

### 服務車輛速度

| 車輛類型 | 基礎速度 (格/tick) |
|---------|-------------------|
| 消防車 | 3 |
| 救護車 | 3 |
| 垃圾車 | 2 |
| 靈車 | 2 |

### 行程估計

```
行程時間 = ceil((路徑長度 / 速度) × (1 + 壅塞率))
```

壅塞率基於路徑上的壅塞路段和全局車輛密度估算。

### 設施分區

設施可以被分配到特定行政區，僅回應該區域的事件。未分配的設施回應所有區域。

## 警察服務 (PoliceService)

### 警局負載系統

警局具有容量限制（預設 1000），超載時犯罪減少效果降低。

#### 每人警力需求

```
需求 = 0.3 × 加權乘數
```

**住宅居民**（依教育程度）：

| 教育程度 | 乘數 | 需求 |
|---------|------|------|
| NONE | 2.0 | 0.6 |
| ELEMENTARY | 1.1 | 0.33 |
| HIGH_SCHOOL | 0.6 | 0.18 |
| UNIVERSITY | 0.3 | 0.09 |

**工作場所工人**（依區域類型）：

| 區域 | 乘數 | 需求 |
|------|------|------|
| 工業 | 1.5 | 0.45 |
| 商業 | 1.0 | 0.3 |
| 辦公 | 0.5 | 0.15 |

每位市民同時產生住宅需求（依教育）和工作場所需求（依區域）。

#### 超載效果

犯罪減少效果 = 基礎效果 × min(1, 1/loadRatio)

- 負載率 ≤ 1.0：犯罪減少正常
- 負載率 2.0：犯罪減少效果減半
- 負載率 5.0：犯罪減少效果僅 20%

### 犯罪減少

- 每個覆蓋該格的警局: 犯罪率 -30（受負載率縮減）
- 上限: 犯罪率最多減少 -60

### 犯罪率計算（SimulationLoop）

```
基礎犯罪率 = min(50, 人口 × 0.02)
每格犯罪率 = 基礎犯罪率 + 警察犯罪減少值 × 負載效率
```

## 消防服務 (FireService)

### 消防局負載系統

消防局具有容量限制（預設 2000），超載時火災損害增加。

#### 每人消防需求

```
需求 = 0.3 × 加權乘數
```

**住宅居民**（依入住率）：

```
乘數 = 1 + occupancyRatio
```

| 入住率 | 乘數 | 需求 |
|--------|------|------|
| 0% | 1.0 | 0.3 |
| 50% | 1.5 | 0.45 |
| 100% | 2.0 | 0.6 |

**工作場所工人**（依區域類型）：

| 區域 | 乘數 | 需求 |
|------|------|------|
| 工業 | 2.0 | 0.6 |
| 商業 | 1.2 | 0.36 |
| 辦公 | 0.8 | 0.24 |

#### 超載效果

火災損害隨負載率從 10% 遞增至 80%：

| 負載率 | 損害 | 說明 |
|--------|------|------|
| ≤ 1.0 | 10% | 正常覆蓋 |
| 1.0~3.0 | 10%→80% 線性 | 逐漸惡化 |
| ≥ 3.0 | 80% | 等同無覆蓋 |

### 火災機制

#### 起火概率

```
基礎起火概率 = min(0.02, 0.001 + 人口 × 0.000005)
每 tick 以此概率嘗試起火
```

起火時隨機取樣 10 個格子，找到有區域建築的格子即起火。

#### 火災過程

1. 起火 → 建立 ActiveFire（持續 3 ticks）
2. 每 tick 倒數
3. 完成後結算損害：
   - **有消防覆蓋**: damage = 10%（受負載率影響）
   - **無消防覆蓋**: damage = 80%

#### 焦黑判定

```
若 damage ≥ 0.5 → 建築變為焦黑 (reserved = BURNED)
```

焦黑建築：
- 渲染為深灰色，無燈光
- 不產生收入
- 不計入容量
- 2% 機率/成長 tick 被建商自動清除

#### 火災風險

基於道路距離：
- 無消防局: 風險 = 1.0
- 覆蓋範圍外: 風險 = 0.8
- 覆蓋範圍內: 風險 = (道路距離 / 預算) × 0.5

## 醫療服務 (HealthService)

### 健康加成

- 每個覆蓋該格的醫院: +20 健康值
- 上限: +35

### 醫院負載系統

醫院具有容量限制（預設 1500），高污染地區的居民會增加醫院使用量。

#### 每位市民醫療需求

```
需求權重 = 0.3 + 0.3 × (住所污染值 / 255)
```

| 污染值 | 需求權重 | 說明 |
|--------|---------|------|
| 0 | 0.3 (30%) | 正常就醫率 |
| 128 | 0.45 (45%) | 中等污染 |
| 255 | 0.6 (60%) | 高污染，使用量翻倍 |

#### 城市負載率

```
負載率 = 全市覆蓋市民加權需求總和 / 全市醫院容量總和
```

#### 負載率對死亡率的影響

| 負載率 | 死亡率乘數 | 說明 |
|--------|-----------|------|
| ≤ 1.0 | 0.3 | 醫院正常運作 |
| 1.0 ~ 2.0 | 0.3 → 1.0 線性 | 逐漸惡化 |
| ≥ 2.0 | 1.0 | 等同無醫院覆蓋 |

#### 無覆蓋 + 高污染額外懲罰

無醫院覆蓋的市民，污染直接增加死亡率：

```
污染死亡乘數 = 1 + 0.5 × (住所污染值 / 255)
```

| 污染值 | 死亡率乘數 |
|--------|-----------|
| 0 | 1.0 |
| 128 | 1.25 |
| 255 | 1.5 |

完整死亡率計算詳見[市民系統 — 死亡系統](citizen-system.md#死亡系統)。

## 垃圾處理 (GarbageService)

### 垃圾產生（分區制）

垃圾由 `GarbageSewageProduction` 模組按區域類型計算：

| 區域類型 | 基礎產量 | 每人產量 |
|---------|---------|---------|
| 住宅 | 0.05 | 0.005 |
| 商業 | 0.1 | 0.005 |
| 工業 | 0.2 | 0.01 |
| 辦公 | 0.02 | 0.002 |

```
每棟建築垃圾 = base + perCapita × (居民數或工人數)
城市總垃圾 = 所有建築垃圾總和
```

### 處理流程

1. 焚化：每設施每 tick 燒掉 80 單位垃圾（固定焚燒率）
2. 分配新垃圾到有空間的設施
3. 超出容量（預設 1000/設施）→ 溢出垃圾

### 每週統計

使用 7 天環形緩衝區追蹤每週的產出量和焚燒量。

### 溢出影響

```
污染懲罰 = min(100, 溢出量 × 2)
```

溢出量在 UI 中顯示為「N garbage uncollected」。

### 溢出分級警告

| 條件 | 等級 | 訊息 |
|------|------|------|
| 負載率 > 50% | 黃色 | Garbage piling up |
| 負載率 > 100% | 紅色 | Garbage overflow |

### 設施污染

負載率 > 50% 的設施會產生地面污染：
```
污染量 = round(負載率 × 40)
基礎污染 = 20（每設施格）
污染半徑 = 5（曼哈頓距離）
```

## 污水處理 (SewageService)

### 污水產生（基於用水量）

污水產量由 `GarbageSewageProduction` 模組計算，基於各區域的用水量乘以污水比率：

| 區域類型 | 污水比率 |
|---------|---------|
| 住宅 | 85% |
| 商業 | 90% |
| 工業 | 90% |
| 辦公 | 92% |

```
每棟建築污水 = 該建築用水量 × SEWAGE_RATE[區域類型]
```

### 處理能力

每座處理廠容量 2250 單位。處理廠必須**鄰接道路**且**有電力供應**才能運作。未處理污水 = max(0, 產生量 - 連接處理能力)。

### 水源污染

```
水源污染 = 未處理污水 × 5
```
每個排放口最多排放 80 污染。注意：污水產生的是**水源污染**（非地面污染）。

## 殯葬服務 (DeathCareService)

### 死亡分配

死亡事件由 `reportDeath(x, y)` 處理，系統依**歐幾里得距離**將死亡分配到**最近的墓園**，不受覆蓋範圍限制。無墓園時死亡歸入「未分配」計數。

### 運作流程

每 tick 每座墓園依序：
1. **Phase 1**: 直接火化待處理屍體（每墓園每 tick 處理 5 具）
2. **Phase 2**: 火化儲存中的屍體（剩餘處理量）
3. **Phase 3**: 儲存未處理的屍體（直到容量上限 500）

### 每墓園負載追蹤

每座墓園獨立追蹤：
- `used`: 目前儲存的屍體數
- `pending`: 待處理的死亡數
- `todayReceived` / `todayCremated`: 今日統計
- `deathDaily` / `recentDaily`: 7 天環形緩衝區，追蹤每日死亡/火化數

### 墓園覆蓋外顯示

UI 顯示「N outside coverage」而非「Overflow」，更準確描述無覆蓋區域的狀況。

未處理的屍體（pending + 未分配）會造成 -20 幸福度懲罰。

## 設施運作條件 (Facility Operational)

所有市政設施（電廠、水廠除外）必須同時具備**電力**和**供水**才能運作：

```
isFacilityOperational(x, y, infraType) =
  (hasPower || 電力豁免) && (hasWater || 供水豁免)
```

| 豁免類型 | 豁免設施 |
|---------|---------|
| 電力豁免 | 電廠（power） |
| 供水豁免 | 水廠（water）、污水廠（sewage） |

未運作的設施不提供覆蓋效果，也不處理任何需求。

當設施的運作狀態變更時（例如取得電力/供水，或失去電力/供水），系統會**立即重算所有服務覆蓋**，確保覆蓋地圖即時反映設施狀態。

## 道路距離覆蓋演算法 (Road Coverage Flood)

大多數市政服務使用 Dijkstra 道路距離覆蓋，而非簡單的歐幾里得半徑。

### 道路格通過成本

```
成本 = BASE_COST / (speedLimit × laneFactor)
```

- `BASE_COST` = 100
- `laneFactor` = 車道數 / 2（雙車道 = 1×）
- 更快更寬的道路 → 成本更低 → 覆蓋更遠

### 各服務的覆蓋預算

| 服務 | 預算 |
|------|------|
| 警察 | 30 |
| 消防 | 30 |
| 殯葬 | 35 |
| 醫療 | 40 |
| 垃圾 | 80 |
| 小學 | 20 |
| 高中 | 30 |
| 大學 | 45 |

從設施出發沿道路 Dijkstra 擴散，累積成本 ≤ 預算的格子視為覆蓋。

## 服務覆蓋分數

### 單格服務分數

每個格子的服務分數（0~10）：

| 服務 | 有覆蓋時的分數 |
|------|--------------|
| 電力 | +2 |
| 供水 | +2 |
| 警察 | +1 |
| 消防 | +1 |
| 垃圾 | +1 |
| 醫療 | +1 |
| 教育 | +1 |
| 殯葬 | +1 |

### 城市服務覆蓋率

`getResidentialServiceRatios()` 計算所有住宅建築的各服務覆蓋比率（0.0~1.0），用於城市層級的幸福度和吸引力計算。

### 城市服務覆蓋分數

```
分數 = 電力覆蓋率 × 2 + 供水覆蓋率 × 2
     + 警察覆蓋率 + 消防覆蓋率 + 垃圾覆蓋率
     + 醫療覆蓋率 + 教育覆蓋率 + 殯葬覆蓋率
     + (平均污染 < 10 ? 1 : 0)
```

## Overview Services 頁面

原本分開的 Infrastructure 和 Services 分頁已合併為統一的 **Services** 頁面，顯示所有設施的負載狀態：
